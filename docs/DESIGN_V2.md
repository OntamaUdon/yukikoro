## 1. コンセプト

> 歩いて育てた雪玉を、いる場所の「塔」に積む。見知らぬ誰かが、その上に、もっと小さな雪玉を積む。
> みんなで積んだ塔の高さを、1週間、県ごとに競う。

- 自分だけでは塔を作れない（自分の雪玉の上に、自分の雪玉は積めない）。
- 動機は 4 つ: ①自分の雪玉が土台になって、人が積んでくれる ②近くに塔ができた通知 ③週ごとの県別順位と殿堂 ④塔のそばでの記念写真（AR）。
- **一番のリスクは「人が少ない場所で、積んでくれる人がいない」こと。** 設計では解けない。14 章の試験で確かめる。

### やらないこと
文字・画像の投稿、チャット、フレンド、プロフィール写真、リアルタイムの位置共有、バックグラウンドの位置取得、広告、課金（今回は無し）、Android、運営の「ゆきんこ」による自動の手助け（**不要と決定**）。

| 用語 | 意味 |
|---|---|
| 雪玉 (ball) | 歩数で育つ、持ち歩く雪玉。1人に1つ。 |

## 3. 雪玉の大きさ［確定］

持っている雪玉の大きさは、**「前におくか積んでから歩いた歩数」** で決まる。上限は無い。

```
直径(m) = 0.029 × (歩数)^(1/3)        （体積が歩数に比例する）
```

| 歩数 | 直径 |
|---|---|
| 41 | 10 cm |
| 1,100 | 30 cm |
| 5,100 | 50 cm |
| 41,000 | 1 m |
| 328,000 | 2 m |
| 1,000,000 | 2.9 m |

- 歩数は HealthKit の歩数。旧版の「はじめて開いたときまでは数えない」（`GameState.baseline`、`credited`）の仕組みを使い回す。
- 持っている雪玉の歩数 = `walkedSteps の合計 − 最後におく/積んだときの合計`（端末の中にだけ保存）。
- **けずる**: 持っている雪玉は、好きな大きさまで **けずって小さく** できる（歩数は戻らない）。塔の比率に合わせるために使う。大きくは戻せない。［仮：UI の見せ方］

## 4. 塔のルール［推奨で確定。数値は設定データ］

### 4.1 積む

| 設定名 | 値 | 意味 |
|---|---|---|
| `stackRatio` | 0.8 | 積む雪玉の直径は、いまの一番上の直径の **0.8 倍以下**。 |
| `minBall` | 0.10 m（約41歩） | これより小さい雪玉は、おけない・積めない。 |
| `minBase` | 0.30 m（約1,100歩） | 土台にできる最小の大きさ。 |
| `stackRadius` | 50 m | 自分の位置から、塔の保存座標まで、この距離以内の塔にだけ積める。 |
| `baseSpacing` | 50 m | **完成していない塔が 50 m 以内にあるとき、新しい土台はおけない**（積むだけ）。完成した塔は、場所をふさがない。 |
| `dailyLimit` | 20 | 1日における・積める回数（端末ごと）。 |

- **積めない場合**: ①自分の雪玉が大きすぎる（けずれば積める） ②一番上が自分の雪玉 ③完成した塔 ④距離が遠い。
- **自分の雪玉の上に、自分の雪玉は積めない**: 一番上が自分の雪玉のときだけ禁止。A→B→A のように、間に他の人がいれば、同じ人が何度も参加してよい。［確定］
- **完成**: 一番上の直径 × `stackRatio` < `minBall`、つまり一番上が約 12.5 cm より小さくなったら、完成。
- **高さ**: 塔の高さ H = 雪玉の直径の合計（接する球を積んだ高さ）。
  - 例: 土台 1 m から、毎回ちょうど 0.8 倍で積むと、11 個で完成し、H ≒ 4.57 m。
  - H は、土台の直径の最大 5 倍まで（0.8 倍の等比級数）。だから、勝つには「大きな土台」と「その上を詰める人たち」が要る。

### 4.2 国内のみ
土台をおけるのは、日本国内だけ（逆ジオコーディングで国が JP のとき）。海外では閲覧のみ。［推奨で確定］

## 5. 位置情報とプライバシー［確定］

**サーバーに載せる位置は、土台をおいた場所に近い「ランダムな点」だけ。** ユーザーの現在位置は載せない。

### 5.1 保存座標の作り方
1. 現在地を、緯度経度から、**50 m 四方の格子** に切る。
   - 緯度: 50 / 111,320 度 ごと。
   - 経度: 50 / (111,320 × cos(緯度)) 度 ごと。
2. 現在地が入っている格子の **中のランダムな点**（一様乱数）を保存座標にする。
3. 積むときの距離の判定は、**端末の現在地 と 保存座標** で行う。積んだ人の位置は保存しない。

### 5.2 そのほかのプライバシー
- 時刻は、サーバーが付ける `creationDate` だけ。通知の文面に、場所や時刻を書かない。
- 持ち主は、**ハッシュ化した ID** と、**決まった言葉の組み合わせの名前** だけ（5.3）。
- 位置は **「アプリ使用中」の許可だけ** を求める。バックグラウンドでは取らない。
- 写真（11 章）は、端末の中にだけ保存する。アップロードしない。

### 5.3 名前［推奨で確定］
- 自由入力は **無し**。「形容詞 + 動物」の組み合わせ（例: ふわふわのペンギン）を、初回に自動で付ける。言葉の一覧から、選び直せる。
- 一覧は、ふつうの語だけ。禁止語の確認は要らない。審査では「ユーザーが入力した文字は表示されない」と書ける。
- 名前は、**週の終わりに確定した順位表（殿堂）にだけ** 出す。塔の画面には出さない（場所が分かる画面に、名前を出さないため）。

### 5.4 出会い・待ち伏せへの対策
- 場所は、50 m 格子の中の乱数。細かい場所は使えない。
- 名前・連絡手段・プロフィールが無い。塔の画面には持ち主が出ない。
- 積まれたことは、**完成のときと、自分の塔が積まれたときの数だけ** 通知する（時刻と場所は書かない）。
- 年齢の目安は、**12+**。
- 通報（9 章）があった格子には、塔をおけなくする（設定データに格子の一覧）。
- ［見送り］学校・幼稚園の近くに置けない制限は、最初は入れない。地図の施設データで判定できるか、後で調べる。

## 6. 不正と荒らしへの対策（軽いものだけ）

CloudKit にはサーバー側の処理がない。**判定は端末側。報酬を軽くして、不正の価値を下げる。**

| 問題 | 対策 |
|---|---|
| 位置のごまかし | `CLLocation.sourceInformation.isSimulatedBySoftware` / `isProducedByAccessory` が真なら、おく・積むを止める。`horizontalAccuracy` > 50 m なら止める。速度 > 約 4 m/s（車・電車）なら止める。完全には防げない。**それ以上は頑張らない**（ユーザーも了承）。 |
| 一人で複数端末 | 止められない。許す。報酬は飾りのポイントだけ。日の上限。 |
| 小さい塔で場所をふさぐ | 土台に最小 30 cm（約1,100歩）を求める。 |
| 量産 | `dailyLimit`、`baseSpacing`。 |
| 同時に積んで衝突 | 8 章の方式で、後から来た方を、無効にする。 |
| 数字の書きかえ（塔の高さ） | 順位は、上位だけ、雪玉の記録から計算し直して確かめる（8.3）。 |
| 人が集まって迷惑 | 通報で、その格子の塔を消す・おけなくする。 |

## 7. 期間と順位［確定: 1週間］

- 期間は **1 週間（月曜 0:00〜日曜 24:00、日本時間）**。`periodId` = `"2026-W47"`（ISO 週番号。日本時間で計算）。
- 期間の終わりに、その週の塔を **そのまま固定**（新しく積めない）。週が変わると、新しい塔だけが見える。
- **順位**: 塔の高さ H が大きい順。都道府県ごとの上位と、全国の上位。同じ高さのときは、完成が早い順。
- **殿堂**: 前の週の上位（都道府県ごと、全国）の高さと、**その塔に雪玉を積んだ全員の名前**。場所は書かない。
- 順位の計算は、サーバーではなく、各端末が行う（8.3）。前の週の塔は、1 週間は読めるように残す。
- 日付は、サーバー時刻（`creationDate`）を基準にする。端末の時計は信用しない。
- **試験版**: `periodId` は `"beta-<番号>"`。番号は、**公開の 1 件のレコード（`BetaClock`）** に入れ、ボタン「週を終える」で +1 する（全員の端末が、読んで合わせる）。本番の版は、この番号を見ない。

## 8. データ（CloudKit 公開データベース）

コンテナ: `iCloud.com.ontamaudon.yukikoro`。公開データベースだけ使う。

### 8.1 なぜ「雪玉 1 つ = 1 レコード」にするか
他人が作ったレコードを書きかえるには、**全員に書きかえを許す** 必要があり、書きかえ放題になる。そこで、**雪玉は、それを積んだ人が作る、書きかえない記録** にする。塔の状態は、雪玉の記録から決める。

### 8.2 レコードの種類

**Tower**（土台をおいた人が作る。**あとから書きかえない**）

| フィールド | 型 | 備考 |
|---|---|---|
| `location` | Location | 保存座標（5.1）。**検索できる** |
| `periodId` | String | 検索できる |
| `prefecture` | Int | 都道府県コード 1〜47（逆ジオコーディング） |

**Ball**（積んだ人が作る。あとから書きかえない）

| フィールド | 型 | 備考 |
|---|---|---|
| `towerID` | String | 塔の recordName。検索できる |
| `index` | Int | 0 = 土台。この塔の中での順番。並べかえできる |
| `diameter` | Double | メートル |
| `cumHeight` | Double | この雪玉までを積んだときの塔の高さ（**積んだ人の申告**。並べかえできる。順位に出す前に計算し直す） |
| `ownerHash` | String | 持ち主のハッシュ（iCloud のユーザー ID を、アプリ固有の塩でハッシュ化） |
| `nick` | String | 決まった言葉の組み合わせ（5.3） |
| `look` | Int | 飾り（12 章） |
| `periodId` | String | 検索できる |
| `prefecture` | Int | 検索できる（県別の順位に使う） |

> 実装済みのスキーマの手順書は `docs/CLOUDKIT_SETUP.md`。**他人のレコードを書きかえる操作は無い**（積む = 新しい `Ball` を作る）。塔の高さのキャッシュを持たず、`Ball.cumHeight` で順位の候補を探し、上位だけ雪玉の記録から計算し直して確かめる。

**Report**（誰でも作れる）: `tower`、`reason`（Int）。管理者が CloudKit Dashboard で見て、対処する。

**BetaClock**（試験版だけ使う。誰でも読める・書ける）: `seq`（Int）。名前は `current` の 1 件だけ。ボタン「週を終える」で `seq` を +1。

**Config**（管理者だけが書ける。全員が読める）: 設定データ（`stackRatio`、`minBall`、`minBase`、`stackRadius`、`baseSpacing`、`dailyLimit`、`blockedCells`、ポイントの数値、`environmentTag` など）。**アプリを更新せずに、数値を変えられる。** 読めないときは、アプリに埋め込んだ初期値を使う。

### 8.3 衝突と、書きかえへの備え
- 積む手順:
  1. 塔の雪玉を、`index` 順に読む。
  2. 4.1 の条件で、積めるか確かめる。
  3. `Ball`（`index` = いまの最後 + 1）を作る。
  4. 数秒後に、もう一度読む。**同じ `index` が複数あれば、`creationDate` が早いものだけ有効、残りは無効**（`recordName` で決着）。
  5. 無効だったら、持っている雪玉を、元の大きさに戻して、「先に積まれました」と出す。
- **有効な雪玉の列** = `index` 順に並べ、先頭から、比率・最小・「前と同じ持ち主でない」の条件を満たすものだけ。条件を破ったものは、無視する（書いた人の雪玉も、戻す）。
- **順位**: `Ball` を `periodId`（と県）で絞り、`cumHeight` の大きい順に取って、同じ塔をまとめる。**候補の塔だけ、`Ball` の記録から高さを計算し直して確かめる**。偽の `cumHeight` は、確かめで落ちる。
- 塔の一覧（地図）は、`location` の近くの検索 + `periodId` で取る。

### 8.4 インデックスと権限（CloudKit Dashboard で手作業）
- **CI のビルドは署名なし → CloudKit が使えない。TestFlight は本番環境。** だから、**スキーマは Dashboard（Web）で手で作り、本番へ反映する**。この文書の表が、その手順書になる。
- インデックス: `Tower.location`（検索）、`Tower.periodId`（検索）、`Tower.prefecture`（検索）、`Tower.height`（並べかえ）、`Ball.tower`（検索）、`Ball.index`（並べかえ）、`recordName`（検索）。
- 権限: `Tower`、`Ball`、`Report` は「誰でも読める / ログインした人は作れる / 書きかえは作った人だけ」。`Config` は「誰でも読める / 管理者だけが書く」。

## 10. ポイントと飾り［仮。数値は設定データ］

目的は、「飾りで自分らしさを出す」と、ちょっとしたごほうび。強い動機にはしない。

- ポイントを得る:
  1. 自分の雪玉の上に、他人の雪玉が積まれたとき: + 使った歩数 / 20
  2. 塔が完成したとき、参加者全員に: + 使った歩数 / 10
  3. 週の終わりの順位: 県 1 位の塔の参加者 + 1,000、全国 1 位 + 5,000、殿堂の称号
- 1 日のポイントに、上限を付ける（複数端末の対策）。
- 使い道: 雪玉の見た目（色合い、帽子、マフラー、にんじん、枝の腕）を買う。`Ball.look` に入れて、他の人の画面にも出る。
- **塔を雪だるまらしく見せる**: 一番上の雪玉に顔（目・鼻・口）を付ける。帽子などの飾りは、持ち主の `look` を使う。

## 11. 写真（AR）［試験のあとに作る］

ユーザーの案: 「現在の GPS 座標、雪だるまの座標、スマホの写真の角度から、だいたいの位置・大きさ・角度で、写真の中に雪だるまを置く」。

### 11.1 検討の結果
- **GPS と方位だけで自動で置く方式は、使わない。** 誤差が大きすぎる。
  - 塔の保存座標は、わざとずらしてある（最大約 35 m）。
  - 現在地の誤差は、数 m〜10 m。
  - 方位（コンパス）の誤差は、10〜15°。
  - 合わせると、数十 m ずれて、「そこに無い」写真になる。
- **採用する方式（ARKit）**: GPS は、「写真を撮れる資格（塔の 50 m 以内）」を判断するためだけに使う。塔は、**ARKit の平面検出で、いま見えている地面の上に、実物の大きさで置く**。
  - 土台 1 m の塔なら、本当に 1 m。持ち主が、地面をタップして、置く場所を決める。向きは回せる。
  - 一番近い塔（50 m 以内）のうち、実際の高さの塔を出す。
- 方位の矢印（「塔はこっち」）は、あとから足せる。［見送り］
- ARKit の位置アンカー（ARGeoAnchor）は、対応する都市が限られるので使わない。

### 11.2 仕様
- 塔の画面に「写真」ボタン。**50 m 以内でないと押せない。** 端末が ARKit に対応しないときは、ボタンを出さない（`UIRequiredDeviceCapabilities` に `arkit` を入れない）。
- 撮った写真は、写真ライブラリに保存（「追加のみ」の許可）。アップロードしない。共有は、OS の共有シートだけ。
- カメラ（`NSCameraUsageDescription`）と、写真の追加（`NSPhotoLibraryAddUsageDescription`）の許可を書く。
- **ARKit は、実機でしか動かない。** CI のシミュレーターでは確かめられない。実機の TestFlight で確かめる。

## 12. 画面

### 12.0 見た目と地図［確定］
**見た目（やわらかいニューモーフィズム + 雪）**
- 背景は、雪のような、うす青みの白（夜は、深い青みの灰色）。カードやボタンは、背景と同じ色で、左上に白い光、右下に青みのかげを付けて、浮かせる。押すとへこむ（内がわのかげ）。
- 色は、雪の白・うす青・やわらかい水色。強い色は使わず、アクセントは 1 色（水色〜青）だけ。
- **読みやすさを優先**: 文字は、背景とはっきり差が付く濃い色（コントラスト比 4.5 以上）。押せる所は、かげだけでなく、形・アイコンでも分かるようにする。
- 昼と夜（ダーク）の両方に対応する。
- 旧版の `Storybook`（かわいい絵本風）は、使わない。

**地図**
- Apple の地図（MapKit）の標準地図。色をおさえた（muted）もの。お店などの印は出さない。
- カメラは、**南の斜め上空から北を向いて**（`heading` = 0）、**傾き（pitch）約 75°**。高さは、いまの場所から約 400 m 手前。端末が、その傾きを許さないときは、許される最大にする。
- ビルは、`elevation: .realistic`（対応する都市だけ立体）を使う。見づらければ、平面（`.flat`）にできるよう、1 か所のフラグで切りかえる。
- 塔の印は、**高さに応じて縦に長く**描く（高さの見やすい誇張。例: 24pt + 18pt × H^0.6）。雪玉を積み重ねた形。


画面は、旧版の見た目（Storybook の部品、角丸のカード、丸いフォント）を使い回す。**見せ場は、3D の塔と雪玉。**

1. **地図（メイン）**
   - Apple の地図（MapKit）。現在地と、近くの塔の印。
   - 上に、今日の歩数（大きく）と、持っている雪玉の大きさ。
   - 塔が多いときは、まとめて数字で表す。
   - 「おく／積む」ボタン（近くに塔があるか・条件を満たすかで、変わる）。
2. **塔の画面**（印をタップ）: 3D の塔、高さ、積まれた数、積む／写真／通報。持ち主の名前は出さない。
3. **持っている雪玉**: 大きさ（cm と、近い物との比べ。旧版の「ひと ×1.4」）、けずる、成長の様子。
4. **おく／積む**: 条件の説明（足りないときは、理由を 1 行で）、確認。
5. **写真（AR）**: 11 章。
6. **記録（アルバム）**: 自分が参加した塔（週ごと）、集めたポイントと飾り、撮った写真への入口。
7. **順位と殿堂**: 今週の県別・全国の上位（高さ）。前の週の殿堂（名前つき）。
8. **設定**: 名前の選び直し、通知、プライバシーの説明、許可の案内。

## 13. 通知と試験版の分け方

### 13.1 通知（CloudKit の購読）
- 近くに新しい塔ができた: `location` 近くの条件で購読。アプリを開くたびに、現在地で作り直す。
- 自分の雪玉の上に積まれた: `Ball` が、自分の `ownerHash` の塔に作られたら。
- 塔が完成した／週が変わって順位が出た。
- 文面は、「近くに雪だるまが生まれました」「あなたの塔が 3.2 m になりました」など。**場所・時刻・人は書かない。**

### 13.2 試験版（TestFlight）と本番の分け方
TestFlight も本番の CloudKit に書く。試験のデータが、本番に混ざらないように、**試験版は `periodId` に `beta-` を付ける**（`AppEnvironment.isBeta`）。本番の版は、`beta-` の塔を見ない。

**試験版だけに出る「テスト」画面（設定の中）**
- 週を終える（`BetaClock` を +1。順位と殿堂をすぐ確かめられる）
- 歩数を足す（+100 / +1,000 / +10,000 / +100,000）
- テスト用に位置を指定する（地図で選んだ塔の位置に、「いる」ことにする。1 人でも積める）。位置のごまかしの確認（6 章）を、このときだけ外す
- 雪玉の大きさを、直接指定する
- 今日のおく・積む回数の上限を、リセットする
